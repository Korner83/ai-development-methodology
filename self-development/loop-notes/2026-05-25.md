## What didn't work — Run 2 operational issue

**Agent role + write permission interaction.** First Run-2 attempt spawned the Opus cold-read agent in the `Explore` role. Explore is read-only (no Edit/Write tools). The agent completed the cold-read correctly and returned ~43 findings as text, but couldn't apply them to the file. Lost ~5 minutes plus the cost of one Opus agent run when the orchestrating session had to re-spawn in `general-purpose` role.

**Root cause:** [`AUTONOMOUS_LOOP.md "fresh session" definition](../AUTONOMOUS_LOOP.md#operational-definition-of-fresh-session) requires "no prior turns referencing this project" and "ideally a different model family," but says nothing about agent role / tool availability. The loop's prompt step 6 ("CROSS-AI VALIDATION") implies fresh = read-only because cross-AI validation is non-destructive, but **cold-reads need write permission to land findings.** Cross-AI validation and cold-reads are not the same operation, but both use "fresh session" language.

**Suggested methodology addition** (surface for maintainer; not auto-applied per Constraint 1):

> Add a sentence to `AUTONOMOUS_LOOP.md` "Operational definition of fresh session" or to `methodology/10_testing_and_verification.md "Cross-AI validation"`:
>
> _"Fresh-session agents that must land output in a file (e.g., cold-read findings, classification tables) need a role with Write/Edit tools — use `general-purpose` or a project's equivalent, not a read-only role like `Explore`. Read-only roles are correct for verification (cross-AI Done-means checks) but wrong for production work."_

This is a one-sentence clarification, not a methodology rewrite. Ship in the next patch release or fold into BL-0009/0010's classification + summary work.
