## Rubric (this project's tailored area set)

The methodology project is docs-only, so the standard product-shaped rubric (UX, frontend, backend, security, etc.) does not apply. Project-tailored areas reflect this project's actual surfaces:

| Area | What 10/10 means for the methodology |
|---|---|
| **Doc completeness** | Every load-bearing concept has a doc; no gaps where an adopter would have to derive a missing rule. |
| **Doc clarity** | A fresh contributor can apply each rule after one read. Cold-read findings on clarity are sparse. |
| **Doc currency** | No stale claims; examples match current canonical forms; cross-doc rules consistent. |
| **Cross-doc consistency** | Same rule stated in one place; restatements explicitly cross-linked; no drift between docs. |
| **Adopter discoverability** | A new adopter finds the project, knows what it does, knows what to read first. |
| **Tool compatibility** | Works as-shipped with at least 3 AI tools natively; documented adaptation path for others. |
| **Self-improvement velocity** | Cycle runs end-to-end without maintainer authorship per fix; aggregate quality rises across cycles. |
| **Governance integrity** | Hard rules enforced; escalate-on-doubt works; cross-AI gates catch what implementing sessions miss. |
| **Examples + reference material** | Adopter-facing examples + cheatsheet present + accurate to current methodology version. |

Thresholds (Closed beta target): **min 7/10 per area, average 8/10 across all** (one notch below the standard 8/9 — closed beta is "trustworthy enough for ~50 strangers," not GA).

## Limitations of this eval

**Self-assessment caveat.** Per doc 12's rule "Use cross-AI for scoring, not the implementing session," this eval was conducted by the same session that authored v1.16.0. Scoring is biased toward charity. **A fresh cross-AI session should re-score the same rubric as a check** before the closed-beta milestone is declared. Surfacing as a follow-up item.

**Single eval is a snapshot.** Trajectory matters more than point-in-time score. Re-eval at Run 6 (next cadence point) to see whether the discoverability score moves after the distribution-plan activation.
